# Requirements Document

## Introduction

This feature integrates the Quiz Champ registration flow with the existing Satyalok payment gateway backend, which uses PhonePe as the payment processor. Currently the quiz-champ backend uses a mock payment service. This spec replaces that mock with a real server-to-server call to the payment gateway, handles the PhonePe redirect callback, and enforces fixed registration fees per batch group (JUNIOR / SENIOR).

The payment gateway backend is a separate running service. The quiz-champ backend communicates with it over HTTP. The frontend never calls the payment gateway directly.

## Glossary

- **Payment Gateway Service (PGS)**: The existing `satyalok-payment-gateway-backend` Node.js service that wraps PhonePe and handles donation and quiz registration payments.
- **Quiz Champ Backend (QCB)**: The `quiz-champ/backend` Express/TypeScript service that manages participant registration.
- **PhonePe**: The third-party payment processor used by the PGS.
- **Merchant Transaction ID**: A unique string generated by the QCB (prefixed `QC26`) that identifies a single payment attempt across both services.
- **Batch Group**: The registration category for a participant — either `JUNIOR` or `SENIOR`.
- **Registration Fee**: The fixed amount in INR charged per batch group at the time of registration.
- **Payment Session**: A transient object returned to the frontend after OTP verification, containing enough information for the frontend to redirect the user to PhonePe.
- **Callback URL**: The QCB endpoint that PhonePe (via the PGS) redirects to after a payment attempt completes.
- **Participant**: A person registering for the Quiz Champ event, stored in the QCB MongoDB database.

## Requirements

### Requirement 1

**User Story:** As a quiz registration participant, I want to pay the correct fixed fee for my batch group, so that I am charged the right amount without manual intervention.

#### Acceptance Criteria

1. WHEN a participant selects the JUNIOR batch, THE Quiz Champ Backend SHALL set the registration fee to ₹100 INR.
2. WHEN a participant selects the SENIOR batch, THE Quiz Champ Backend SHALL set the registration fee to ₹150 INR.
3. WHEN the registration fee is determined, THE Quiz Champ Backend SHALL derive the fee solely from the participant's batchType field and SHALL NOT accept an amount from the client request.

---

### Requirement 2

**User Story:** As a quiz registration participant, I want to be redirected to PhonePe to complete payment after OTP verification, so that my payment is processed securely.

#### Acceptance Criteria

1. WHEN a participant's OTP is verified successfully, THE Quiz Champ Backend SHALL generate a unique Merchant Transaction ID prefixed with `QC26`.
2. WHEN a Merchant Transaction ID is generated, THE Quiz Champ Backend SHALL call the Payment Gateway Service `POST /quizChampOrder` endpoint with the participant's name, mobile number, batch group, and the computed registration fee.
3. WHEN the Payment Gateway Service returns a redirect URL, THE Quiz Champ Backend SHALL return that redirect URL to the frontend in the payment session response.
4. IF the Payment Gateway Service call fails or returns an error, THEN THE Quiz Champ Backend SHALL return an HTTP 502 error to the frontend and SHALL NOT mark the participant's payment status as COMPLETED.

---

### Requirement 3

**User Story:** As a quiz registration participant, I want my registration to be confirmed automatically after a successful PhonePe payment, so that I receive my admit card without manual steps.

#### Acceptance Criteria

1. WHEN PhonePe completes a payment, THE Payment Gateway Service SHALL redirect the user's browser to the Quiz Champ Backend callback URL with the Merchant Transaction ID as a query parameter.
2. WHEN the Quiz Champ Backend receives a callback with a Merchant Transaction ID, THE Quiz Champ Backend SHALL call the Payment Gateway Service `GET /status?id={merchantTransactionId}` endpoint to verify the payment status.
3. WHEN the payment status response indicates success, THE Quiz Champ Backend SHALL update the participant's `paymentStatus` to `COMPLETED`, assign a unique roll number, and generate the admit card data.
4. WHEN the payment status response indicates failure, THE Quiz Champ Backend SHALL update the participant's `paymentStatus` to `FAILED`.
5. IF the status check call to the Payment Gateway Service fails, THEN THE Quiz Champ Backend SHALL log the error and return an HTTP 502 response.

---

### Requirement 4

**User Story:** As a quiz registration participant, I want to be redirected to the correct result page after payment, so that I can see my registration outcome immediately.

#### Acceptance Criteria

1. WHEN the Quiz Champ Backend processes a successful payment callback, THE Quiz Champ Backend SHALL redirect the participant's browser to the frontend success page with the participant ID as a query parameter.
2. WHEN the Quiz Champ Backend processes a failed payment callback, THE Quiz Champ Backend SHALL redirect the participant's browser to the frontend failure page with an error indicator.

---

### Requirement 5

**User Story:** As a system operator, I want the quiz-champ backend to authenticate with the payment gateway service, so that only authorised callers can initiate quiz registrations.

#### Acceptance Criteria

1. WHEN the Quiz Champ Backend calls the Payment Gateway Service, THE Quiz Champ Backend SHALL include a shared secret API key in the `x-api-key` request header.
2. IF the shared secret API key is missing or invalid, THEN THE Payment Gateway Service SHALL return an HTTP 401 response and THE Quiz Champ Backend SHALL propagate the error as an HTTP 502 to the frontend.
3. THE Quiz Champ Backend SHALL read the shared secret API key from an environment variable named `PGS_API_KEY` and SHALL NOT hard-code the value in source code.
